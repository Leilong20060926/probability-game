## 一、完整遊戲規則

### 1. 牌庫（每張地圖開始時 16 張全部重洗）

| 代號 | 牌 | 張數 | 說明 |
|---|---|---|---|
| H | 橫向 | 4 | 道路牌 |
| V | 縱向 | 4 | 道路牌 |
| B | 彎道 | 2 | 道路牌 |
| X | 十字 | 1 | 道路牌，可代替任意 1 張方向牌（H、V 或 B） |
| R | 落石 | 5 | 破壞牌，不能拿來鋪路 |

- 道路牌共 11 張，全部共 16 張。
- 每張牌權重相同，抽牌一律**不放回**。
- 抽到種類 t 的機率 = 牌庫中 t 的張數 ÷ 牌庫總張數。

### 2. 路段種類（需求以 (H, V, B) 表示）

| 名稱 | 需求 | 程式代號 |
|---|---|---|
| 平直通道 | 橫×2 → (2,0,0) | HH |
| 上坡通道 | 橫＋縱 → (1,1,0) | HV |
| 縱向豎井 | 縱×1 → (0,1,0) | V |
| 雙層豎井 | 縱×2 → (0,2,0) | VV |
| 短橫道 | 橫×1 → (1,0,0) | H |
| 狹窄捷徑 | 彎×1 → (0,0,1) | B |

### 3. 三種地圖

每張地圖的結構都是：`起點 → 第一段 → 岔路 → A 線或 B 線 → 終點`。

| 地圖 | 第一段 | A 線 | B 線 |
|---|---|---|---|
| 地圖一 | HH | B → HV → V | HH → HV |
| 地圖二 | HV | B → HH → H | VV → H → H |
| 地圖三 | B | HH → VV → V | VV → B → VV |

- 開局時，以及每次拿到金幣要換下一張地圖時，電腦從三種地圖**隨機抽一張，各 1/3**。
- 每次抽都獨立、可重複，和牌、和之前的結果都無關。
- 地圖的定義要放在設定檔或資料結構裡，方便之後調整，不要寫死在邏輯裡。

### 4. 一張地圖的流程

**(1) 開局發牌**

- 從洗好的 16 張依序抽牌，直到手上有 5 張道路牌。
- 過程中每抽到 1 張落石：翻開、移出遊戲，第一段的落石加需求 a 加 1，然後繼續抽。
- 牌庫抽空就停止。

**(2) 回合動作**

玩家在目前路段每回合選**一個**動作：

- **鋪路**：交出一組手牌，張數必須剛好等於「路段需求張數 + a」，而且能滿足需求。
  - 指定的方向牌（H、V、B）不夠時，可以用十字補；十字的張數必須足以補上所有缺口：`Σ max(0, need[t] − pay[t]) ≤ pay[X]`。
  - 多出來的 a 張是「任意牌」，任何道路牌都可以（包含十字）。
  - 同一手牌可能有多種付法，**每一種不同的組合都是不同的動作**，因為留下的牌不同。
- **硬挖**：交出任意 3 + a 張道路牌，直接通過目前路段。手牌不夠就不能硬挖。即使能鋪路也可以選擇硬挖。
- **換牌**：牌庫不是空的時候才可以。棄 1 張手牌（移出遊戲），再抽 1 張；抽到落石就照 (4) 處理後繼續抽，直到抽到 1 張道路牌或牌庫空。

**(3) 通過一段之後**

- 付出的牌移出遊戲。
- 前進到下一段，`a` 歸零。
- 補牌補到手牌 5 張；過程中抽到的落石加在**新的目前位置**上。
- 若下一個位置是**岔路**：先補牌（補牌時抽到的落石先累積在 `a`），補完後玩家看著手牌選 A 線或 B 線，累積的 a 帶到所選路線的第一段。選了就不能回頭。選岔路**不算一個動作**。
- 若剛通過的是最後一段，就到達終點：**不補牌**，直接翻終點牌。

**(4) 落石**

- 一抽到就翻開，目前位置的 a 加 1，然後補抽 1 張。
- 重抽沒有次數限制，直到抽到道路牌或牌庫空。

**(5) 地圖失敗**

牌庫已空，而且手牌既付不出鋪路，也付不出硬挖。只要牌庫還有牌，就一定可以換牌。

### 5. 整局流程與計分

- 最多玩 3 張地圖。
- 1 張金礦終點和 2 張金幣終點，以等機率排列在三次地圖上。等價的說法：
  - 第 1 張地圖的終點是金礦的機率為 1/3；
  - 前一張是金幣時，第 2 張是金礦的機率為 1/2；
  - 第 3 張一定是金礦。
- **金幣**：coins + 1，重新抽地圖、牌庫重洗，進入下一張地圖。
- **金礦**：遊戲結束，得分 `X = 60 + 20 × coins`。
- **任一張地圖失敗**：`X = 0`，已得金幣不計分。
- X 只可能是 0、60、80、100。

### 6. 時間與其他結束條件（只有規則引擎需要，機率計算忽略）

- 每局限時 300 秒，從按下「開始探勘」起算，以伺服器時間為準。切換分頁、關閉頁面都不暫停。
- 時間到時，未完成的操作不算，以 X = 0 結算。
- 玩家按「提前結束」並確認：`X = 0`，紀錄為中途結束。
- 同時觸發時的優先順序：
  1. 挖到金礦（該動作算完成，不再補牌）
  2. 牌用盡
  3. 超時

## 二、機率分析方法（不可用模擬當結果）

### 1. 單張地圖的狀態

state = (位置 pos, 落石加需求 a, 手牌 (h_H, h_V, h_B, h_X), 牌庫 (d_H, d_V, d_B, d_X, d_R))

pos ∈ {第一段, 岔路, A1.., B1.., 終點}。

### 2. 遞迴定義（全部用有理數）

- `draw(pos, a, hand, deck, n)`：還要抽 n 張道路牌時的期望通關率。
  - 若 n == 0 或牌庫空：回傳 `best(pos, a, hand, deck)`。
  - 否則對每種牌 t，機率為 `deck[t] / Σdeck`：
    - t = 落石：`draw(pos, a + 1, hand, deck − t, n)`
    - t 是道路牌：`draw(pos, a, hand + t, deck − t, n − 1)`
- `best(pos, ...)`：
  - `pos == 終點`：1。
  - `pos == 岔路`：A、B 兩條路線第一段的 best 取最大值。
  - 其他：所有合法動作做完之後的價值取最大值；沒有合法動作時為 0。
    - 鋪路或硬挖後到達終點：價值 1。
    - 鋪路或硬挖後還沒到終點：`draw(下一位置, 0, 剩下手牌, deck, 5 − 剩下手牌張數)`。
    - 換牌：`draw(pos, a, 手牌 − 1 張, deck, 1)`。
- 單張地圖通關率：`p_i = draw(第一段, 0, 空手牌, 初始牌庫, 5)`。
- 所有函式都要記憶化，key 用狀態 tuple。

### 3. 平手規則（只影響「期望動作數」與策略輸出，不影響通關率）

- 鋪路／硬挖的候選組合，依 pay = (H, V, B, X) 由小到大的字典序列舉；接著才列舉換牌，依棄 H、V、B、X 的順序。
- 只有「嚴格大於」目前最佳值時才替換。
- 岔路平手時選 A 線。

### 4. 整局分布

每次換地圖都重新隨機抽地圖、16 張重洗，所以每次地圖是否通關獨立、同分布。由全機率定理：

p = (p1 + p2 + p3) / 3
P(X=60)  = p/3
P(X=80)  = p · 2/3 · p · 1/2 = p²/3
P(X=100) = p³/3
P(X=0)   = 1 − (p + p² + p³)/3

- CDF 是右連續階梯函數。
- 另外輸出 E[X]、E[X²]、Var(X)、P(S) = P(X > 0)。

### 5. 策略比較與參數比較

同一套程式要能用參數切換以下情境：

- 落石張數
- 手牌上限
- 岔路固定走 A 或固定走 B（其他決定仍取最佳）
- 禁止硬挖
- 改單張地圖的路段需求

### 6. 期望動作數

- 照最佳策略（含上面的平手規則）計算每張地圖的期望動作數。鋪路、硬挖、換牌各算 1 個；選岔路不算。
- 每局期望動作數 = 平均每張地圖動作數 × (1 + 2p/3 + p²/3)。

### 7. 提示模式（給遊戲網頁用）

給定任一狀態，回傳每個合法動作做完後的通關機率，並標出最佳動作。

### 8. 蒙地卡羅模擬器

- 照同一套規則和最佳策略實際發牌（可指定亂數種子）。
- 輸出 p̂ 和 95% 信賴區間、模擬的 PMF。
- 測試要確認精確值落在區間內：用 100,000 局以上，或對單張地圖各跑 200,000 次。

## 四、注意事項

- **規則細節不要自行改**：落石的處理、岔路在補牌之後才選、到終點不補牌、換牌要牌庫有牌，這些都會影響數值。若測試數值不符，先檢查這幾點。
- **時間**：基準設定在一般電腦上應該幾秒內算完，有記憶化就不會太慢。
- **機率計算全程用有理數**，只有輸出顯示時才轉小數。期望動作數可以用浮點數。
- **輸出格式**：計算工具要能從命令列執行，例如 `node tools/route-version --scenario base`，並輸出 JSON，內容包含 p_i、p、PMF、CDF、E、Var、P(S)、期望動作數。
- **後端紀錄**：要新增「抽到的地圖種類」、目前路段、落石加需求 a 這幾個欄位。規則版本號要更新，不同版本的資料不要混在一起統計。
- **完成後請回報**：改了哪些檔案、如何執行、所有測試結果，以及任何和本文規則不一致、需要我決定的地方。
